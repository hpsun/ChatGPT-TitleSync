2026-11-11 — AppleScript reserved-selector candidate

The compile-only diagnostic in run 43035186223, Swift job 130572026758, for commit d90f7d3ca16cbd24b7f521b8baa18a0e947984e6, succeeded and identified the actual offending token as run inside app's run(). The UTF-16 error range was {4883, 3} for the exact CRLF source and {4787, 3} for its in-memory LF copy. The repeated CLI :189 location was not sufficient to identify the failing source statement; the earlier popup edits did not resolve it. All four native compilation steps still passed in that run.

This candidate changes that one call to app's |run|(). Apple's AppleScriptObjC translation guide documents vertical-bar escaping for Cocoa method names that conflict with AppleScript terminology. The selector remains the Cocoa run method. A focused static review found no other bare calls from the same command-name set; existing |error|: parameter labels remain escaped. No other selector was changed.

The source change is a candidate pending the next actual Mac CI compile. The diagnosis compiled source only; it never executed the event loop, a script handler, the AX monitor or the application UI. Native runtime, settings, icons and sign-in startup remain unverified by this work.

2026-11-11 — Publication candidate and Windows acceptance

Added and changed

  • Shared 45 artwork and independent implementations in C#, AutoHotkey Basic/v1.1/v2, PowerShell, Python, Go, Rust, Swift and Objective-C. Each branch has English and Chinese build/run guides.
  • Fresh-install defaults are 2 seconds for foreground source reads and 5 seconds per background source. Existing valid saved settings remain effective; explicit startup arguments override the corresponding saved values. Native cached-caption maintenance remains independently scheduled at one second.
  • Tray/menu settings save the foreground/background pair and reschedule the existing controller. Source results from an earlier settings generation are rejected. Foreground reads use fresh source data; known inactive generic-caption resets can be repaired from the same-identity cache.
  • Windows source checks now include the public settings callback and hidden-startup fixtures in PowerShell 5.1 and 7. The source audit excludes runtime caches, logs, private diagnostics, downloaded toolchains and binaries from the source package.

Fixed

Observed problem Cause and correction Verification / public source
The first settings window could contain complete controls but remain invisible after launching the process Hidden. STARTUPINFO.wShowWindow can override the first ordinary ShowWindow request. Go, Rust, C# and PowerShell display paths now explicitly reveal their owned settings windows with SetWindowPos rather than relying on that first Show. C#/PowerShell request activation separately. This was a native visibility issue, not evidence that UI Automation could not locate the controls. A separate owned WinExe confirms actual Hidden startup flags, an initially hidden native Show, explicit reveal, and unchanged foreground focus. Final running-app settings checks passed. See C#, PowerShell, Go, Rust, and fixture.
A slow foreground source interval could be confused with an unresponsive C# reader, and consuming only on that interval could miss a fresh source snapshot. Source observation sequence/time and one-second heartbeat sequence/time are separate. The helper reads on the configured source interval; the parent consumes new observations on the native maintenance tick. A healthy source gap does not repeatedly cancel the independent background role. Controlled cold-attach, long-interval, new-sequence, role-change and old-observation rejection checks; monitor and reader.

Verified, with explicit limits

Nine Windows runtime routes were actually run: C#, AHK Basic, AHK v1.1, AHK v2, Windows PowerShell 5.1, PowerShell 7, Python, Go and Rust. The same three existing windows were reused. Each route completed a valid foreground generic-caption reset, a background reset, settings save/reopen/restore, source/header comparison and normal exit observations. Python's final settings recheck used 7/17 seconds; the other routes used 3/10 before restoring 2/5.

The recorded reset times are single observations, not benchmarks or a performance ranking. A bound native settings/menu handler was exercised; this does not claim a physical shell right-click test for every implementation, long-term monitoring, installation acceptance, or all ChatGPT versions. See the support matrix and validation details.

The macOS Swift, Objective-C, Go/Darwin and Rust/macOS branches remain Experimental: no native Mac SDK build or real AX run. Remote CI had not run at this documentation freeze. Its actual status must be observed in GitHub Actions after publication, not inferred from local checks.

2026-11-10 — Settings save and failure-path fixes

PowerShell replacement saves could fail with “The path is empty” after an initial settings file already existed. PowerShell could coerce the third File.Replace argument from $null to an empty string. Branch-owned first/replacement save, missing-directory, invalid-input, failed-save rollback and temporary cleanup fixtures. See Basic guide, v1.1 source, v2 source.

In one 60-second Windows experiment with two confirmed conversation navigations, a single Document.NameProperty / TreeScope.Element subscription received zero callbacks, although source/header observations showed the changes and native foreground/name-change metadata events arrived. Header-text events were not subscribed and the document locator was not rebound. This does not prove every possible ChatGPT event route is unavailable. Event-only monitoring was not adopted; the 2/5-second source fallback remains. See known issues.
