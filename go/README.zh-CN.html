Go：ChatGPT-TitleSync / ChatGPT 标题同步助手

English · 项目主页

Windows x64构建及隔离测试已验证。macOS仍为Experimental，CI编译检查不等于Mac本机GUI／持续监听实测。实现独立使用Go与原生接口，不调用C#监听程序。

环境与构建

Windows使用Go 1.22及以上、Windows x64；Win32/COM绑定仅依赖标准库，无需cgo或MSVC。本机验证使用已核对官方SHA256的便携Go SDK，未安装到系统。

.\build.ps1
# Go不在PATH时：
.\build.ps1 -GoExe C:\path\to\go.exe

正式Windows构建请使用build.ps1，其临时生成*_windows_amd64.syso、运行测试并以-trimpath构建，结束后清理资源对象。直接go build会绕过基准图标嵌入。Go原生运行部分无需cgo或MSVC；正式图标构建另需上述Windows PowerShell／.NET组件。

实验性macOS需要Go、Xcode命令行工具及macOS SDK，并启用cgo，链接AppKit、ApplicationServices、CoreFoundation、Objective-C运行库及libproc。

CGO_ENABLED=1 go build -trimpath -o chatgpt-titlesync-go .

此Mac命令供未来本机构建使用，尚未验证。

发布构建固定使用-trimpath，去除编译元数据中的本地源码/构建目录前缀。当前trimmed Windows候选与完整专项使用同14份产品源码/模块文件，38项受控及自有检查通过，其最终真人读源复测另行记录；此选项不修改产品源码，也不生成ZIP交付。

运行、间隔及控制

.\chatgpt-titlesync-go.exe --interval 2 --background-interval 5
.\chatgpt-titlesync-go.exe --pause
.\chatgpt-titlesync-go.exe --resume
.\chatgpt-titlesync-go.exe --stop
.\chatgpt-titlesync-go.exe --once --read-only

Mac使用./chatgpt-titlesync-go及相同参数。--interval范围1..3600秒，缺省2秒。--state-dir PATH选择私有控制目录，暂停／恢复／停止时须使用同一目录。--once只取执行瞬间的前台窗口，然后退出并还原自有改动；终端在前台时可能没有采样。

协议分三层：前台来源缺省每2秒fresh读取，不以记住的名称代替；已知后台窗口的generic原生标题每秒用缓存修复，不重新读来源；独立串行后台worker缺省每窗5秒刷新来源，并低频发现未知后台窗口。前台不等待后台来源队列。自定义原生标题保留；提交前复核身份、前后台角色及缓存版本。

Windows各版本共用互斥体Local\TdxChatGptTitleStandalone与停止事件Local\TdxChatGptTitleStandalone.Stop。Mac使用本Go实例的私有控制文件，不宣称跨语言互斥。暂停和正常退出仅还原仍匹配的自有标题；强制终止不能保证还原。

配色45与固定／随机图标

缺省为固定配色45，使用统一的45–52透明资源。通过「扫描间隔设置…」打开三个不可编辑下拉框：图标模式「固定／随机」、固定配色「45–52」、随机周期「每日／每小时／每5分钟」。固定配色框仅在固定模式可用，周期框仅在随机模式可用。保存先验证所需资源并提交草稿，取消保持原已提交选择。运行中同步托盘和本程序已打开的设置窗图标，不改写可执行文件或已固定快捷方式。

Windows 请保留随项目分发的 assets/themes/45.ico 至 52.ico；保存随机模式前要求八个资源均可加载。基准别名为 ICO、PNG、ICNS。查找支持可执行文件旁的 themes/，以及原目录结构中的相对 assets/themes/。正式Windows构建已将基准45的七个分辨率嵌入EXE资源。共用的资源生成器使用PowerShell／.NET BCL生成Win32 RES，再由Windows .NET Framework 4.x的cvtres.exe转换并规范化COFF；不另装资源编译器或外部库。所需Windows PowerShell与%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\cvtres.exe缺失时明确失败，不默默产出通用文件图标。

Windows 各实现共用 HKCU\Software\ChatGPT-TitleSync 中的下列值；图标设置不混入本语言的前台／后台时间设置文件。

值名 类型 含义／缺项默认值

FixedIcon DWORD 45–52，默认45
IconPeriod REG_SZ day（默认）、hour、5min
RandomIcon DWORD 上一次随机配色，45–52
IconSlot REG_SZ 上一次已提交的本地时间槽

随机模式使用全部八种配色，排除前一个实际显示的配色。启用随机模式或改变周期时立即选择一次；同一有效时间槽内重启沿用已保存配色。时间槽按本机时间生成：每日 YYYYMMDD，每小时 YYYYMMDDHH±HHMM，每5分钟 YYYYMMDDHHbb±HHMM，其中 bb 为分钟整除5后的两位编号00–11。UTC偏移区分夏令时回拨后的重复小时。每秒一次的轻量界面时钟只比较时间槽，不读取ChatGPT、不启动读取器；暂停标题同步也不停止图标轮换。

主题注册表、开机自启动与间隔文件共享回滚边界；应用图标失败时保留旧图标和原已提交设置。轮换所需资源缺失时保留最后可用图标，同一时间槽仅记录一次有限诊断，不反复弹窗。旧自有图标句柄在托盘和程序窗体切换完成后释放。已存主题字段非法时报告诊断并以45显示回退，不偷偷改写偏好。worker、probe、once、read-only和控制入口不初始化主题控制器。

时效、隐私与验证

调度按单调时钟截止时间推进，跳过错过的轮次，而不是每次读取完成后再等待完整间隔。Windows隔离读取器使用本程序自身，超时上限4秒，只使用保留的自有子进程句柄。启动或提供器延迟可能超过1秒，1秒间隔不代表1秒内出结果。

Mac前台使用原生前台应用及AXFocusedApplication／AXFocusedWindow；低频发现目标后台窗口可读取AXWindows；必须确认标题可写并回读，拒写不会报告成功。运行输出只包含状态、窗口和PID元数据，不含会话名称或正文；内部读取器通信按用途包含根名称。

验证报告涵盖实际租约／调度逻辑的模拟前台切换、原生COM条件ABI、自有离屏STATIC窗口，未验证真实ChatGPT集成或Mac行为。

后台间隔及验证范围

使用--background-interval N，范围5..3600，缺省5秒。后台原生标题检查独立保持1秒；未知窗口按低频节奏发现，只有有效来源结果才能建立缓存。前台与后台来源独立受控，后台一次只处理一个来源任务，不阻塞前台队列；慢读取或排队会延长实际观察时延，不能宣称1秒内完成。

本次三层fixture覆盖后台generic不读来源修复、保留custom并刷新记忆、未知窗口建缓存、每窗到期时间、版本／身份／旧结果防护，以及后台任务挂起或很慢时前台仍可处理。Windows为隔离测试，不代表真实ChatGPT整体验收。Mac仍标Experimental，本机未做Mac原生编译或AX验证。

托盘菜单与扫描间隔设置

Windows 常驻运行现在提供原生托盘图标。右键菜单含「启用窗口标题」「开机自启动」「扫描间隔设置…」「退出并还原标题」。设置窗分别输入前台扫描间隔（1–3600 秒，默认 2 秒）与后台源刷新间隔（5–3600 秒，默认 5 秒）。保存校验、写入本语言私有设置文件，并在当前驻留进程中生效；不会启动第二个标题写入者。禁用或暂停时仅还原本进程仍持有且未被外部改动的标题。修改间隔会废弃旧队列结果并重新安排调度，Windows 在途读取器由其自身保留的子进程句柄取消。

已知非活动窗口标题被软件改回的轻量检查仍固定每 1 秒一次，只使用缓存标题，不重新读取对话源；它不受上述两个源读取间隔控制。下次正常启动加载已保存设置；显式 --interval 或 --background-interval 分别覆盖该次运行的对应值，之后通过菜单保存才持久化。--once 仅使用命令行值且不建托盘；--no-tray 明确选择无菜单的驻留命令行模式。

本次受控测试包含自有隐藏的原生设置窗、合法/非法输入、启用状态保存与重读、保存失败不改变运行设置、热更新调度和正常退出还原。这些不替代真实 ChatGPT 常驻联动验收。

当前软件名称为 ChatGPT-TitleSync / ChatGPT 标题同步助手。Windows 旧互斥体/停止事件 Local\TdxChatGptTitleStandalone 及 .Stop、已有状态目录、原生自动化类名、租约及控制文件格式刻意保留，用于承接已有设置，并阻止旧版和改名版 Windows 驻留程序同时写入标题。兼容身份中的历史名称不是当前品牌。默认前台 2 秒、后台 5 秒，已有合法保存值继续优先。

开机自启动（缺省开启）

托盘右键「开机自启动」以勾选状态表示并立即保存/应用。设置窗口也提供同名复选框，保存才提交，取消不改变已保存选择；菜单成功变更后会同步已打开的设置框，同时保留尚未提交的间隔输入。系统注册或文件保存失败会报告错误并保留原已提交状态；文件提交失败时回滚本次注册表变更。

Windows 各语言共享 HKCU\Software\ChatGPT-TitleSync 中的 DWORD AutoStartEnabled：缺项默认开启，显式 0 在换语言、重启后继续沿用。正常驻留取得原跨版本互斥锁后，才在 HKCU\Software\Microsoft\Windows\CurrentVersion\Run 的值 ChatGPT-TitleSync 写入当前带引号的绝对 EXE 路径，不附带测试或 state-dir 参数。换语言时替换同一项，不新增多条开机项。正常退出不会取消已保存的开机启动选择。

worker、probe、自测、once、read-only 和控制请求均不注册。read-only 驻留使用命令行/控制文件而不建托盘，避免只读上下文通过界面新增启动项。本实现不支持 --settings CLI 参数，会在取得互斥锁/注册之前拒绝；请通过托盘打开设置。

私有设置文件同步保存 autostart_enabled，旧文件缺项默认 true；正常 Windows 启动以共享注册表偏好为准。新增离线验证仅用自有临时注册表子键，不碰真实 Run 项或共享偏好，覆盖默认开启、关闭继承、系统/文件失败回滚、菜单/复选框同步及保存/取消。本次构建仍待根控制器进行真实启动验收。

名称替换与共用系统辅助程序

名称替换缺省为空规则列表，不包含个人前缀、本机规则或从其它程序迁移的预设。各语言监听程序调用同一份经过审查的系统辅助程序：Windows为ChatGPT-TitleSync.Rules.exe（.NET Framework Unicode／Regex），macOS为chatgpt-titlesync-rules（Foundation／AppKit）。发布此功能需要随包提供该辅助程序；Rust没有新增crate，Go没有新增外部Go模块。

使用前先构建辅助程序：

# 在当前语言目录中，Windows：
powershell -NoProfile -File ..\shared\windows\Build.ps1

# 在当前语言目录中，macOS：
sh ../shared/macos/build.sh
# 也可指定输出目录：
sh ../shared/macos/build.sh /tmp/titlesync-rules-build

使用单独输出目录时，把生成的辅助程序随监听EXE放在同一目录；源码目录结构也支持已知shared/windows／shared/macos位置。程序不从规则偏好读取可执行命令，也不通过PATH查找辅助程序。需要同时打包本地帮助页。

托盘菜单和设置窗口都增加名称替换…入口。规则按顺序执行，可启用、删除和调整顺序。literal按字面、区分大小写、非重叠全替换；regex使用对应操作系统引擎。数字捕获替换支持$0～$99、${0}～${99}和$$；高级正则语法存在Windows／macOS差异。允许空替换；失败、无效、空白、控制字符或超长结果均回退完整的已验证原名。

当前对话名列表来自本监听运行／设置目录的私有title-rule-sources.bin CTS1快照，不额外查询ChatGPT。快照无效或不存在时仍可手工输入示例，并显示快照时间。建议正则只根据选中的示例／文字转义生成候选，先展示解释、正则、替换和结果，必须明确点击使用规则再保存。打开、预览或取消不创建持久规则文件。详见名称替换帮助。

共享规则位于Windows的%LOCALAPPDATA%/ChatGPT-TitleSync/title-rules.json或macOS的~/Library/Application Support/ChatGPT-TitleSync/title-rules.json。扫描间隔、启动项和图标设置保持独立，保存这些设置不会抹掉规则。实际个人规则、来源名称快照、worker包和运行日志不应发布。

监听保留未经替换的已验证原名，显示标题与退出恢复租约分开保存。规则变化只推进显示修订，丢弃过时异步结果，并仅改写仍由本实例持有且等于上次写入值的标题；不重排来源截止时间或取消来源读取。前后台缺省2秒／5秒与原有1秒后台原生标题维护节拍保持。格式化使用本实例创建的独立worker，1500毫秒硬截止，按原名与规则字节缓存成功／回退；未变化的维护不会反复启动格式化进程。人工标题、窗口创建身份和退出恢复保护保留。

本功能新增的规则／三层假后端检查仅用私有文件和内存原生状态；可选的owned-worker夹具只启动并终止自己创建的无界面进程。既有未筛选Windows测试还会使用GUID临时注册表键及自有原生控件，因此不能把未筛选的go test／cargo test结果称为纯私有文件测试。即使CI编译与纯格式化用例通过，也不等于macOS本机GUI／持续监听已完成实测。
