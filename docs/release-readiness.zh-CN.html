截至2026-11-12：ChatGPT-TitleSync仓库与v0.1.0公开预览版已经公开；名称替换功能分支正在验证，未建立新Release，产品名称与版本不变。 中文名为ChatGPT 标题同步助手。用户已选MIT，源码仍须包含仓库LICENSE。此前未发布／待批准说法保留为历史状态。

既有登录自启动契约

登录自启动已经缺省已开；托盘／菜单可直接勾选，设置中同项按保存提交、取消不改。Windows各实现共用当前用户Run值和DWORD偏好；启用超长命令会被拒绝，退出不取消下次登录登记。见启动说明。名称替换不改变此契约。下方旧九路线设置／重置观测属于旧源码修订，不能证明新规则处理已经验收。Mac登录／LaunchAgent行为仍为Experimental，未完成真实Mac验收。

名称替换候选

新增显示处理缺省为空规则，支持有序字面／正则规则，并使用共享系统Unicode配套程序；不内置个人规则或自动迁移。当前对话名示例来自已核实原名的快照，建议规则须明确点采用规则及保存。规则变化只使显示状态失效，不改变来源读取频率或原标题还原记录。见名称替换帮助。

本功能目前的Windows验证使用私有文件、模拟原生状态、自有控件和仅CLI工作进程，不是正常驻留或真实ChatGPT界面验收。最新C#／PowerShell／其它语言结果将按组件汇总，不借旧测试凑合计。

目标协议与验收边界

最终目标分三层：

  1. 前台ChatGPT窗口按可配置间隔直接fresh读取来源，缺省2秒，不能用记住的来源代替前台读取。
  2. 每秒检查已知后台窗口的原生身份／标题。应用把标题改回generic时，直接用记住的标题恢复，不重新读来源；保留自定义标题，身份改变清缓存，未知窗口不凭空造缓存。
  3. 后台来源低频刷新，每窗缺省5秒、可配置，单独一个串行worker；未知后台也可低频建缓存。前台优先，不能等待后台来源队列。完成时仅在身份一致且原生标题仍generic或本程序上次写入值时更新，保护自定义名。

Windows分支已有三层来源／缓存的受控检查和本机构建／解析证据。这是本地源码候选的审核边界，不是所有语言的真实应用完整验收。全部Mac后端仍为Experimental。下列实际SDK编译／CLI检查点与当前待验证修订、真实AX／菜单／编辑器／登录验收必须分开；旧foreground-only测试与新协议检查明确分开。

离线审计与仓库文件选择

只需Python 3.10及以上及标准库：

python -m unittest discover -s tools/tests -p "test_release_audit.py" -v
python tools/release_audit.py --allowlist --no-zip --output-dir "$env:TEMP/ChatGPT-TitleSync-file-review"

目录尚无独立Git仓库时，--allowlist明确只取已审阅的源码、文档和45资源。初始化并暂存后，省略--allowlist检查tracked快照。两种模式都拒绝越界或未审阅的tracked文件；Git-index模式还拒绝工作文件与暂存内容不一致。

审计按实际包内文件集核对必需文件、文档相对链接／锚点、前台2秒/后台5秒缺省源码标记、45资源哈希、MIT及已有源码哈希索引。拒绝私有运行证据、validation、日志、备份、SDK、二进制、个人绝对路径和常见凭据形态。模式不能识别所有真实对话名或秘密，仍须人工审阅候选快照。

核准后按正常目录逐文件提交源码、指南、共享45资源与必要伴随源码，本次不上传项目ZIP。可Git clone获取目录树，或在对应语言目录取得单文件并保留其文档要求的依赖。GitHub若自动提供源码归档，是平台生成内容，不是本项目上传的ZIP；先前本地审核压缩包仅作历史留证，不作为交付方式。

审计使用--no-zip输出机读报告和选中文件清单，不生成压缩包。发布方核对每个文件字节，再建立对应blob/tree。根.gitattributes使用* -text保持已审核字节；私有运行数据、下载SDK等不进入仓库。
