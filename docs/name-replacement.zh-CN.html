名称替换

English · 简体中文 · HTML · 项目主页

修改对话名在本机ChatGPT窗口标题中的显示形式。ChatGPT中保存的原对话名保持原样。规则默认空白，不导入其它程序的规则，也不附带个人前缀。

打开规则编辑器

在托盘菜单选择名称替换… / Name replacement…，或点击设置中的对应按钮。规则编辑器由随所选语言实现提供的共用组件打开；分发已编译程序时，请保留配套组件。

  1. 从当前对话中选择已观测到的名称，或手工输入示例。
  2. 添加规则，选择普通文字或正则表达式。
  3. 填写查找和替换；替换留空表示删除匹配文字。
  4. 检查预览，通过上移／下移调整执行顺序。
  5. 点击保存后生效；取消丢弃草稿。

打开编辑器、选择示例、预览或请求建议均不保存规则，也不改变窗口。保存后的规则先处理对话名，再附加原有的— ChatGPT后缀。

从当前对话名选择示例

下拉列表使用正在运行的监听程序已经核实的原始名称，并显示快照时间，便于识别旧资料。它不会扫描聊天历史或把内容发送到服务器。

列表为空时，可以激活相关ChatGPT窗口，等待正常监听取得名称，也可以直接手工输入。尚未观测过的后台窗口可能不在列表里。选择名称只会填入示例框，不会修改对话名称。

原始名称与替换后的显示结果分别保存。修改规则不会增加ChatGPT来源读取，也不会重置前台、后台扫描间隔。

普通文字替换

需要精确替换一段文字时使用。匹配区分大小写，替换全部互不重叠的出现位置。标点、美元符号和反斜杠均按普通字符处理。

示例名称 查找 替换 预览
Work / Example chat A Work / 留空 Example chat A
draft plan — draft notes draft final final plan — final notes
Price $1 $1 $2 Price $2

Work与work不同；此模式中的句点只匹配实际的句点。

正则表达式替换

需要按结构匹配时使用。下表均为教学示例，不会作为默认规则安装。

用途 示例 查找 替换 预览
删除固定前缀 Work / Example chat A ^Work / 留空 Example chat A
保留斜杠后的部分 Team / Example chat B ^[^/]+/\s*(.+)$ ${1} Example chat B
提取完整方括号内名称 [Example chat C] ^\[([^\]]+)\]$ ${1} Example chat C
交换两段内容 North / South ^(.+) / (.+)$ $2 — $1 South — North
匹配实际句点 Example.v2 \. - Example-v2

常见符号

符号 含义
^和$ 名称的开头与结尾
. 一个字符；用\.匹配实际句点
(...) 捕获一部分，供替换内容引用
+、*、? 一次以上、任意次数、可有可无
[abc]、[^/] 集合内字符，或斜杠以外的字符
\s 空白字符
\ 转义符，例如\[、\(、\.

在替换内容中引用捕获组

$1或${1}表示第一个捕获组，依次支持到$99／${99}。$0或${0}表示完整匹配，$$表示实际的美元符号。合法但本次没有匹配到的可选组展开为空；引用不存在的捕获组会被拒绝。

这些引用只在正则模式下有意义；普通文字模式中的${1}就是普通文字。替换框不会把\1当作捕获组引用。

Windows使用.NET正则，macOS使用Foundation的NSRegularExpression。上面的常见示例面向两者编写，但高级语法及Unicode匹配可能不同，须在目标平台预览；配置文件能够读取，不代表其中的高级表达式可以直接跨平台使用。

生成建议方案

选择示例名称后点击建议 / Suggest。程序根据该示例的结构或所选文字，在本地生成候选，例如删除前缀、保留分隔符之后的部分、提取成对括号中的内容。

每个候选都会显示用途、表达式、替换内容和结果。检查后选择使用规则 / Use rule，它才会加入草稿；点击保存才正式生效。用于其它名称时可能得到不同结果，条件允许时应至少预览两个有代表性的示例。

建议不会批量改写所有聊天、修改云端对话名或安装本机专用默认规则。没有适合的结构时，可以自行填写普通文字规则或表达式。

顺序和开关

总开关可绕过整张规则表，并保留已配置内容；每行也能单独启用。已启用规则从上到下依次执行，上一行的输出是下一行的输入。

例如对Work / draft plan，先删除Work /，再将draft替换成final。调整顺序可能改变结果。未启用的行仍可保留，便于以后修改。

ChatGPT 后缀与完整标题

共享编辑器的 Append — ChatGPT / 标题末尾显示ChatGPT 复选框缺省勾选，按保存生效，与 Enable name replacement 及逐行开关独立：替换规则为空或停用时仍可关闭程序追加的后缀。共享 JSON 可选布尔项 append_chatgpt_suffix 缺项按 true，不属于扫描、图标或启动项偏好。

取消勾选只停止本程序追加尾巴，不会删除原对话名本身已有的同样文字。选择样例、生成建议、预览或取消均不提交此项；核实原名、来源节拍、原标题恢复及手工改名保护保持不变。

下例是虚构配置，分别关闭替换和追加后缀：

{
  "schema_version": 1,
  "enabled": false,
  "append_chatgpt_suffix": false,
  "revision": "00000000-0000-4000-8000-000000000001",
  "rules": []
}

格式化协议与边界

--format 保持仅返回名称主体；附加 --caption 返回完整标题，caption模式前端直接采用，不再重复拼尾巴。合法来源原名及格式化主体最多 512个UTF-16码元，正常完整标题含可选10码元 — ChatGPT 后缀时最多 522个。配置存在时，即使替换为空或停用，也须经过caption formatter才能应用后缀选择。

可解码但非法的来源（超过512码元或含控制字符）返回完整原始输入且不加后缀，绝不截断；因此诊断回退可超过正常合法标题上限。损坏UTF-16仍为协议/I/O错误。正常来源读取器在显示处理前另行执行自身边界检查。

Windows 负载边界：自有格式化 worker 的截止仍为 1.5 秒。负载竞争或启动缓慢可导致超时，回退为完整原名加缺省后缀，因此保存的 false 可能尚未生效。失败按原名及规则/辅助程序身份缓存，条件不变的轮询不会重试；重新保存规则、替换/改变辅助程序身份、重启监听，或观测到不同原名，才会刷新该缓存。降低负载后，两种 PowerShell host（5.1、7）分别单独复测同项成功，之前 WorkerTimeout 现场仍保留；不能据此宣称无条件通过，也不承诺完整界面响应必在1.5秒内完成。

四种Windows前端的一次检查模式限制

当前Python、AHK Basic1.0、AHK1.1和AHK2产品的 --once 跳过整个规则客户端，因此忽略已保存替换规则，也忽略 append_chatgpt_suffix=false，使用原名加缺省尾巴。这是当前产品限制，与旧主体formatter API的兼容性不同；不能把常驻模式的行为当作一次检查已遵守用户设置。

错误及回退

已启用规则的查找内容不能为空；表达式或捕获组引用无效时不能保存。替换内容可以留空。

执行失败、超时，或最终结果为空白、含控制字符、过长、只剩ChatGPT时，整条处理链都会回退为完整原始对话名，不使用只改了一半的结果。

最多32行；查找和替换各最多512个UTF-16代码单元，结果同样最多512个。常见字符通常占一个，emoji通常占两个。超过限制会报错，不会悄悄截断。

Windows单个正则匹配超时为100毫秒，整条处理链预算500毫秒；独立格式处理进程还有1.5秒的父进程期限。macOS以可独立结束的处理进程提供硬期限。预览与监听均不在界面线程执行无界正则。

新结果尚在计算时，原有受控标题可能暂时保留至下一次显示更新。其它程序手工修改过的标题继续遵守现有保护；正常退出时仍按原逻辑尝试恢复原生窗口标题。

本地文件与隐私

同一操作系统下，各语言实现共用规则：

  • Windows：%LOCALAPPDATA%\ChatGPT-TitleSync\title-rules.json。
  • macOS：~/Library/Application Support/ChatGPT-TitleSync/title-rules.json。

文件不存在表示规则为空。只有明确成功保存才创建或修改偏好文件；保存前校验并原子替换。修改间隔、图标或开机启动不会覆盖替换规则。

已观测名称保存在单独的本地运行快照中，除非用户主动把某段文字写入规则，否则不会复制到规则文件。请勿公开自己的规则文件、运行快照或含真实对话名的截图。随程序提供的示例均为虚构名称。

构建与验证范围

Windows各实现均使用配套的Unicode组件，包含早期ANSI版本AHK Basic，以获得一致的规则处理；Mac各实现使用Foundation组件。各语言的构建和运行说明见指引目录。

编译、受控格式处理、来源读取及真实桌面验收是不同检查。以支持矩阵所列的实际范围为准；Mac原生运行尚未完成验收时，继续保留Experimental标记。
